199 hand-labelled items say the news corpus carries hazard, not direction — 188 of 199 had no directional sign, but 20 flagged shock risk. It is a signal source, not an execution system.

Do not build a second shadow-trading system. Sopana already has the exits, the ladder, the liquidity gates and twelve days of bug-hunting behind it. The scanner has never sent an order and has no order path at all. The fast route to “fundamental + technical in shadow” is to make the scanner a signal provider to Sopana, not to grow it a second execution engine.

That also matches what each is measurably good at. Sopana reads price and vol. The scanner reads events. Feeding the scanner's per-side tail estimate and event-risk flag into Sopana's verdict is a small interface; rebuilding Sopana inside the scanner is a rewrite.

02 The one-line contradiction blocking the scanner

Worth fixing first because it is small, it is provably wrong, and it is the reason the signal arm has never traded.

Update, 4 August — half of this moved, and it was the less interesting half. The gate was found to be a fixed threshold on a number whose scale changed under it: the weighted-mean aggregator reported 0.54–0.59, synthesis reports 0.30–0.42, and 0.65 was never re-derived when the swap happened. It has been recalibrated to 0.40, the 75th percentile of the synthesis distribution.

That unblocked the signal arm, but it did not touch the ordering — the threshold was never the defect. The ordering is now fixed too. Verticals are still constructed unconditionally, because a condor is assembled from one of each, but they are only offered when confidence clears the gate. The condor no longer passes through the directional check at all. 

def _candidates(self, chain, prediction):
    ...
    put_ok, call_ok = self._sides_allowed(prediction)   # ← tails decide first
    verticals = [...]                                    # ← always BUILT

    if prediction["confidence"] >= self.s.confidence_gate:
        results += verticals                             # ← only the vertical is gated
    if put_ok and call_ok and allow_iron_condor:
        results += self._condors(verticals)              # ← reached on its own merits

What decides a condor now is _sides_allowed(), min_edge_score and the pricing filters — none of which ask which way the market is going. A vertical is short one tail and long a view, so “not sure which way” disqualifies it. A condor is short both tails and holds no view, so the same uncertainty is its precondition. 

def _candidates(self, chain, prediction):
    ...
    if prediction["confidence"] < self.s.confidence_gate:
        return []                                     # ← exits here, always
    put_ok, call_ok = self._sides_allowed(prediction)  # ← never reached
    ...
    if put_ok and call_ok and allow_iron_condor:
        results += self._condors(results)              # ← never reached

The iron condor is the instrument for “no directional view, both tails quiet.” The code builds it. The confidence gate — which runs first — rejects the trade for having no directional view. The scanner declines condors on exactly the grounds that make a condor correct.

_sides_allowed() already says so in its own docstring: “Blocking on a NEUTRAL label asked the wrong question — flat with both tails quiet is the best setup a premium seller gets.” That reasoning was fixed one layer down and the gate above it was left alone. Sopana reached the same conclusion independently: when MIN_DIRECTIONAL_VOTES fails to clear, it sells a condor rather than standing aside.

Gate 8 exists because the scanner was not reliable enough to be trusted with a veto. It aborted on roughly one invocation in eighteen — a native heap abort that killed the interpreter with no traceback. As a standalone research tool that is a nuisance the retry absorbs. As the thing deciding whether Sopana may sell puts, a source that dies silently and leaves a three-hour-old hazard flag behind is actively dangerous.

Diagnosed and fixed 3 Aug. The faulthandler dump named trafilatura's shared lxml parser; extraction is now serialised. So the gate is no longer waiting on a cause — it is waiting on evidence, which is only time: ten consecutive trading days with no lost cycle. It stays a gate precisely because a fix nobody has watched run is a hypothesis.

Reset 5 Aug, on its second day. Three scheduled cycles were lost to a write-path defect — the scanner’s log carries the post-mortem — so the count restarts 6 Aug and the gate moves to ~20 Aug. The gate caught the right thing for the wrong reason: it was written for the heap abort, and what actually cost the cycles was a schema mismatch. It measures lost cycles, which is correct; it simply cannot start counting until the code has been exercised in the branch that matters.

Gate 10 decides what happens on the bad day, so decide it before the bad day. Fail-open is the right default — a missing scanner means Sopana trades exactly as it does today, which is a known quantity. Fail-closed would let an unrelated outage silently halt the book. Pair it with a staleness bound: a hazard flag older than one Sopana cycle is not a signal, it is a stale row, and should be ignored rather than obeyed.

05 What actually moves the date

Four of the ten gates are now pure waiting — Gate 8 joined them on 3 Aug, when the abort stopped being a puzzle and became a countdown. Nothing in the integration shortens them, and nothing in them shortens the integration. What they can do is slip: Gate 8 lost two days on 5 Aug, which is the only date on this page that moved.

The one sequencing decision that matters. Wiring the veto into Sopana is a code change to Sopana. Gate 1 forbids bug-fix version bumps inside its window, and any defect found in fresh integration code is exactly that. So there are two orders, and only one of them is free:

Integrate, then start the clock — the veto lands while the clock is stopped anyway (it cannot start until bug #10 is fixed), and the ten clean days then certify the combined system. Cost to the go-live date: zero.

Start the clock, then integrate — the first defect in the veto code resets the counter, and ten days are spent twice. Cost: two weeks or more.

The alternative, if late Sept is too far away. Ship Sopana alone and add the scanner veto afterwards. That reaches a first live trade sooner, since gates 8–10 drop out. The cost is two go-live events instead of one, and the second lands new code on a system already trading real money — which is when a mistake stops being free.

Worth taking only if the first live fill matters more than the second one being safe. On the current numbers — five closed trades, all on defective code, net −$1,210 — it probably does not.

06 Rules this sequence obeys

One change at a time, with trades in between. Sopana shipped eleven versions in twelve days and has never been stable for three consecutive trading days. That is why Gate 1’s clean-day clock has not started, and it is the single biggest reason live trading is still far away. Every step above is deliberately separated by days, not hours.

Applied on 2 Aug: trend_side_block ships at 0. It is the only one of the four new measures that changes which trades may exist, and landing a behaviour change in the same deploy as the instrumentation meant to evaluate it would leave no clean before-picture. It becomes its own step once there is a week of readings.

Gate 1 resets on behaviour, not on severity — resolved 2 Aug. The checklist said P0/P1 in one place and “any bug” in another. Both are wrong. “Any bug” is unfalsifiable: there is always a log string or an unbinding threshold, so the counter never reaches ten and the gate becomes a permanent block rather than a gate. P0/P1-only fails the other way, and bug #10 is the proof — labelled P2, yet it silently discarded call wings that qualified because the put wing failed an OI check. It earned a P2 because it did not lose money, not because it did not matter.

The replacement is a behavioural test, which cannot be gamed by triage optimism: the counter resets on any bug that changed, or could have changed, which trades open, close, or how they are sized. Observability, logging and cosmetic defects do not. Against the existing log that resets on #1, #2, #3, #4, #6, #7, #9 and #10; not on #8 (proposed, never shipped) or on v1.8.2’s reason codes.

Do not start the clean-day clock while bug #10 is open. v1.8.2 made it visible; its root cause is still unfixed. Gate 1’s second clause forbids a bug-fix version bump inside the window — so starting the clock with #10 unfixed guarantees a reset the moment it is fixed. That is a ten-day timer you already know you will restart. Fix the root cause first: a few days now against ten later.

But #10 currently cannot be observed at all — found 3 Aug. All 61 [GATE] lines since v1.8.2 read iv_rank < 20, so entry selection never runs and v1.8.2’s reason codes have fired zero times. Against the 270 rows in dte25_vix_daily (VIX 13.47–31.05), MIN_IV_RANK = 20.0 needs VIX above roughly 17.0. It closed 3 Aug at 15.77.

This changes the shape of the task, not the ordering. #10 must be fixed by reading the code — the instrumentation added to catch it in the wild cannot report until the tape moves. Waiting for a reproduction is waiting on volatility, which is not a plan. And it is a second reason not to start the clock: a quiet tape means the clock would run on days where Sopana never selected an entry, which certifies nothing.

The scanner feeds Sopana, never the reverse. One order path, one exit engine, one place where risk is sized. A second execution system doubles the surface area that has to earn ten clean days.

Direction is not the product. 188 of 199 labelled items carried no directional sign. The tail gate has passed 28 of 28 cycles. The strategy wins when SPX fails to move sharply — so the questions worth asking are “is premium rich” and “is a shock window open”, and the default trade when both answer well is a condor.

Nothing here is evidence of edge yet. Five closed trades on code with known defects, net −$1,210, and a scanner arm that has never traded. Every number in this document is an input to a decision, not a result. Two of those five closed on 3 Aug at their stop — which is the risk control working, and is still a loss.
